# Availability of data, code and supplementary material

Whether a reader could check the work.

## 1. Data

**Question.** Are the data behind the main results available, and does the paper say where and in what form?

**Why it matters.** Data that others can find and reuse allow a result to be reanalysed, which is how many errors are found. "Available on request" often means unavailable.

**Resolved by.** A repository or archive holding the data for the main results, with an identifier, or a stated reason why the data cannot be shared.

**Benchmark.** [1], [2]

## 2. Code and analysis detail

**Question.** Is the analysis code available, or is the analysis described in enough detail to write it again?

**Why it matters.** Many results depend on analysis choices that a methods paragraph does not capture.

**Resolved by.** The code in a repository, or a description precise enough that an independent implementation would give the same numbers.

**Benchmark.** [2]

## 3. Supplementary material the text relies on

**Question.** Is every supplementary item that the main text cites as evidence actually accessible with the paper?

**Why it matters.** A claim whose evidence sits in material the reader cannot obtain cannot be evaluated.

**Resolved by.** Every cited supplementary figure, table and dataset present and matching its description in the text.

**Benchmark.** None needed: this can be checked directly.
